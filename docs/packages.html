Packages

A package is a Schematic project published under a name. Adding one copies its source into your project's packages folder and pins the exact commit, and a hash of the files, in project.lock, so the project runs the same everywhere.

schematic new report
cd report
schematic add text-tools

Studio's Project tab does the same from the window. The list below is read live from the registry on GitHub, where each package is one small file.

Publishing a package

Any project in a Git repository can be a package: a folder with a project.scm manifest and a src folder of namespaces, with a tag for each release. To list it, open a pull request to the registry that adds packages/<name>.scm and puts the name in index.scm.

{:name "text-tools"
 :description "Small helpers for titles and slugs"
 :license "Apache-2.0"
 :git "https://github.com/collide2954/schematic-registry"
 :subdir "examples/text-tools"
 :versions {"0.1.0" {:tag "text-tools/0.1.0"}}}

Every version names a :tag or a :commit, :license is the package's SPDX expression (the package's own project.scm may say it too), and :subdir points at the package's folder when a repository holds more than one. A package may list :dependencies of its own in its project.scm; adding it brings them along, and schematic packages shows the whole set with licenses. A project can also depend on a package that is not listed, straight from its repository or from a folder next to the project:

schematic add text-tools --git https://github.com/collide2954/schematic-registry --tag text-tools/0.1.0 --subdir examples/text-tools
schematic add my-lib --path ../my-lib
